# Build Local App - Developer Runbook

Date: 2026-08-07

## Purpose

Use this runbook to build the current Tauri desktop version of Portfolio
Manager from a local checkout. This is for developer/local validation, not for a
public notarized release.

For public GitHub Releases, use:

- `design/2026-08-07-github-release-process.md`

## What Gets Built

The current app is made of three pieces:

- `backend/`: FastAPI Python sidecar, frozen with PyInstaller.
- `frontend/`: React/Vite renderer, built into `frontend/dist/`.
- `src-tauri/`: Tauri 2 Rust desktop shell, packaged as a macOS `.app` and DMG.

The local build flow is:

1. Install backend packaging dependencies.
2. Install frontend dependencies.
3. Build the frozen Python sidecar into `src-tauri/binaries/portfolio-sidecar/`.
4. Build the React frontend.
5. Build the Tauri app bundle and DMG.
6. Optionally sign and install the `.app` into `/Applications`.

## Prerequisites

Run these from macOS:

```bash
xcode-select --install
python3 --version
node --version
npm --version
rustc --version
cargo --version
```

Expected toolchain:

- Python 3.11 or newer.
- Node 20 is the current GitHub Actions build version.
- Rust stable new enough for Tauri 2 dependencies.
- macOS 11 or newer for the configured app target.

If Rust is old, update it:

```bash
rustup update
```

## Start From A Clean Checkout

From the repo root:

```bash
cd /Users/mattbriggs/Git/personal-project-portfolio
git status --short
git pull --rebase origin main
```

Do not build a release candidate from a dirty tree unless the dirty files are
intentional local test changes.

## Bootstrap Python Backend

Create or refresh the root virtual environment:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e "backend[dev,package]"
```

The `package` extra installs PyInstaller, which is required by
`scripts/build_sidecar.py`.

Optional backend-only smoke check:

```bash
cd backend
../.venv/bin/pytest
cd ..
```

## Bootstrap Frontend

Install frontend dependencies from the repo root:

```bash
npm install
```

This repository currently uses `npm install` because there is no committed
`package-lock.json`. Once a lockfile exists, prefer `npm ci`.

Optional frontend checks:

```bash
npm run typecheck
npm test
```

## Build The Frozen Sidecar

From the repo root, with `.venv` active or by calling its Python explicitly:

```bash
.venv/bin/python scripts/build_sidecar.py
```

Expected output:

```text
src-tauri/binaries/portfolio-sidecar/
```

The default `onedir` mode is intentional. It starts much faster than onefile
mode and is bundled by Tauri as a resource through `src-tauri/tauri.conf.json`.

## Build The Desktop App

Build the Tauri app from the repo root:

```bash
npm run tauri build
```

Tauri runs the configured frontend build first:

```text
src-tauri/tauri.conf.json -> build.beforeBuildCommand = npm run build
```

Expected outputs are under:

```text
src-tauri/target/release/bundle/macos/
src-tauri/target/release/bundle/dmg/
```

Typical artifacts:

```text
Portfolio Manager.app
Portfolio Manager_2.0.0_*.dmg
```

## Sign And Install Locally

After `npm run tauri build`, use the helper script:

```bash
scripts/install_macos_app.sh
```

The script:

- Locates the built `.app`.
- Signs nested Mach-O binaries before signing the app bundle.
- Uses a Developer ID Application identity if one exists in your keychain.
- Falls back to ad-hoc signing for local-only use.
- Installs the app into `/Applications` by default.

Useful options:

```bash
scripts/install_macos_app.sh --no-install
scripts/install_macos_app.sh --bundle "src-tauri/target/release/bundle/macos/Portfolio Manager.app"
scripts/install_macos_app.sh --dest "$HOME/Applications"
scripts/install_macos_app.sh --identity "Developer ID Application: Your Name (TEAMID)"
```

Ad-hoc signing is enough for your own machine, but it is not enough for a
public GitHub release. Public releases need Developer ID signing,
notarization, stapling, and checksum generation.

## Run The Built App

If installed to `/Applications`:

```bash
open "/Applications/Portfolio Manager.app"
```

If not installed:

```bash
open "src-tauri/target/release/bundle/macos/Portfolio Manager.app"
```

On first launch, the app uses:

```text
~/.portfolio_manager/config.toml
~/.portfolio_manager/portfolio.db
```

Before testing migrations against real data, back up:

```bash
cp ~/.portfolio_manager/portfolio.db ~/.portfolio_manager/portfolio.db.backup.$(date +%Y%m%d-%H%M%S)
```

## Local Validation Checklist

After launching the built app:

- App window opens without using a terminal.
- Dashboard loads.
- Projects, Sessions, Milestones, Weekly Review, and Settings views load.
- Creating or editing one test item persists after app restart.
- The sidecar starts automatically.
- Quitting the app terminates the sidecar.
- No generated build artifacts show as untracked source changes:

  ```bash
  git status --short
  ```

## Common Problems

### PyInstaller Missing

Symptom:

```text
No module named PyInstaller
```

Fix:

```bash
.venv/bin/python -m pip install -e "backend[dev,package]"
```

### Frontend Tools Missing

Symptom:

```text
sh: tsc: command not found
sh: vitest: command not found
```

Fix:

```bash
npm install
```

### Rust Edition Or Tauri Dependency Errors

Symptom: Cargo reports unsupported `edition2024` or dependency resolution
errors.

Fix:

```bash
rustup update
rustc --version
```

Use a stable Rust version new enough for the current Tauri 2 dependency tree.

### App Opens Before Sidecar Is Ready

The UI may briefly show a degraded sidecar state while the frozen backend
starts. The current `onedir` sidecar mode should start quickly. If startup is
slow, confirm you did not build the sidecar in `onefile` mode.

### macOS Blocks The App

For local development, run the signing/install helper:

```bash
scripts/install_macos_app.sh
```

If the helper uses ad-hoc signing, the app is suitable for local testing only.
For a public release, follow the GitHub release process doc and use Developer ID
signing plus notarization.
